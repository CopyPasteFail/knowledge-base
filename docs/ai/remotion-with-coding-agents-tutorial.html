Overview

This guide explains how to use Remotion with coding agents such as Codex, Claude Code, Cursor, or similar agentic development tools.
It focuses on practical workflows: how to set up a Remotion project, how to structure repositories, how to give coding agents useful instructions, how to validate generated video code, and how to avoid brittle or generic output.
Remotion turns video production into software engineering. Coding agents can help build scenes, components, animation logic, render scripts, and pipelines. They should not be treated as a substitute for creative direction, brand judgment, or visual review.

Remotion Mental Model

Remotion is a React-based framework for creating videos programmatically.
A Remotion video is usually built from:
  • React components
  • Props or data
  • Frame-based animation logic
  • Local assets such as images, fonts, audio, and video clips
  • A composition definition with width, height, FPS, and duration
  • A render step that outputs MP4, WebM, GIF, or still images
The core model is:
React components + props + frame number + assets
→ Chromium renders frames
→ FFmpeg encodes the video
→ final output file
A simple Remotion animation might look like this:
import { AbsoluteFill, interpolate, useCurrentFrame } from 'remotion';

export function TitleScene() {
const frame = useCurrentFrame();
const opacity = interpolate(frame, [0, 30], [0, 1]);

return (
<AbsoluteFill background: 'black', color: 'white' }}>
<h1 opacity }}>Product Update</h1>
</AbsoluteFill>
);
}
The important distinction is that Remotion animation should be driven by the current frame, not by browser time.
Use frame-based animation:
const frame = useCurrentFrame();
Avoid browser-time animation for video timing:
setTimeout(...)
Date.now()
requestAnimationFrame(...)
Math.random()
CSS and Tailwind are fine for static styling and layout. Remotion frame-based APIs should drive animation.

What Remotion Is Good At

Remotion is well suited for structured, repeatable, data-driven video generation.
Strong use cases include:
  • Motion graphics
  • Kinetic typography
  • Product demos
  • Website walkthroughs
  • Captioned clips
  • Animated charts
  • Social videos
  • Personalized or batch-generated videos
  • Data-driven templates
  • AI-generated asset composition
  • CI/CD video rendering pipelines
Remotion is not a drag-and-drop video editor. It is also not an AI video generation model. It does not create photorealistic footage from imagination. It can compose photorealistic clips, screenshots, images, or 3D renders if those assets are supplied.

Role of the Coding Agent

A coding agent can be highly useful in a Remotion workflow, but the responsibility boundaries should be clear.
The human provides:
  • Goal
  • Audience
  • Platform
  • Creative direction
  • Brand constraints
  • References
  • Review feedback
  • Final judgment
The coding agent implements:
  • Remotion compositions
  • Scene components
  • Animation logic
  • Typed props and schemas
  • Render scripts
  • Example data
  • Tests and smoke renders
  • Documentation updates
Remotion provides:
  • React-based composition model
  • Frame-based rendering APIs
  • Local and server-side rendering tools
  • Output generation
A coding agent can act as a technical motion-graphics implementer. It can also suggest visual directions. It should not be trusted as the sole source of taste by default.

Installation

Remotion Project Setup

For a new project, start with Remotion’s project generator:
npx create-video@latest
For an automated or non-interactive setup:
npx create-video --yes --blank my-video
cd my-video
npm install
Then start the development studio:
npm run dev
For an existing repo, install Remotion packages locally in the project:
npm install remotion @remotion/cli @remotion/renderer
Project dependencies should be local and lockfile-controlled. Avoid relying on globally installed Remotion runtime packages.

Agent Skill Setup

Remotion provides Agent Skills for coding agents such as Claude Code, Codex, Cursor, and OpenCode. Install it with:
npx skills add remotion-dev/skills
This should be treated as an agent capability, not as part of the application runtime.
The npx skills installer detects supported agent environments and installs the skill into the right agent-specific location.
The skill can be installed globally or agent-environment-wide for convenience. Serious projects should still include repo-local instructions such as AGENTS.md, CLAUDE.md, or equivalent documentation.
Because Remotion skill repository doesn't provide stable package-style versioning, projects that need reproducibility should record the reviewed skill commit or vendor the most important guidance into repo docs.

Optional MCP Setup

The Remotion MCP is a documentation/context layer for AI tools. It is not the renderer.
Distinction:
Skill:
workflow guidance and Remotion best practices for the agent

MCP:
documentation lookup/context for the agent

CLI / renderer:
actual video rendering
Example MCP configuration:
{
"mcpServers": {
"remotion-documentation": {
"command": "npx",
"args": ["@remotion/mcp@latest"]
}
}
}
Use MCP when the coding environment supports it and the agent needs reliable access to Remotion docs.

Recommended setup

Remotion runtime packages:
local dependency in package.json

Render scripts:
package.json scripts

Remotion Agent Skill:
global or agent-environment install for convenience

Repo guidance:
AGENTS.md, CLAUDE.md, DESIGN.md, VIDEO_STYLE.md

MCP:
configured in the editor or agent host
Avoid depending on global runtime tools for project behavior. A project should be reproducible from its repo, package manager lockfile, and documented setup steps.

Common Use Cases

Website or Product Promo Video

A website or product promo video turns an existing product, landing page, or feature into a short video.
Common inputs:
  • Website repo
  • Live website URL
  • Screenshots
  • Brand tokens
  • Product copy
  • Logo and fonts
Common outputs:
  • Launch video
  • Landing-page promo
  • Feature highlight
  • Social post
  • Product teaser
Recommended architecture:
  • Use a monorepo if the video and website share brand code or data.
  • Use a standalone video-studio repo if the video system should remain independent.
  • Use screenshots and live URLs as references, not as the only source of truth.
    A live URL can help the agent understand the visual direction, but it is not a reliable replacement for source code, design tokens, fonts, components, or brand guidelines.

Standalone Video-Studio Repo

A standalone video-studio repo is a strong pattern when video generation is its own reusable creative or production system.
This repo can contain:
  • Brand guidelines
  • Design tokens
  • Remotion templates
  • Reusable scene components
  • Example props
  • Render scripts
  • Agent instructions
  • Video style docs
  • Local assets
It can generate many types of videos:
  • Product launch videos
  • Feature demos
  • AI/news updates
  • Social clips
  • Ads
  • Recruiting videos
  • Personal brand videos
  • Educational explainers
  • Website walkthroughs
Example structure:

This pattern works well when videos are generated across multiple products, brands, or channels and should not be tightly coupled to one website application.

Batch or Personalized Videos

Remotion is a strong fit for batch-generated videos.
Example workflow:
CSV / JSON / API rows
→ validate input data
→ pass props into one Remotion template
→ render one video per row
→ upload outputs to storage
Use cases:
  • Personalized sales videos
  • Customer reports
  • Weekly analytics summaries
  • Dynamic social clips
  • Automated status updates
  • Personalized onboarding videos
The key requirement is a clear data contract. The agent should not hardcode production content directly into components. It should define typed props, example JSON, and validation rules where appropriate.

Product Walkthroughs

Product walkthroughs often use screenshots or recordings as source material.
The Remotion layer can add:
  • Zoom and pan motion
  • Captions
  • Callouts
  • Highlight boxes
  • Chapter titles
  • Music and voiceover timing
  • Branding
  • Outro screens
This is different from recreating the whole product UI in Remotion. For walkthroughs, it is often better to use actual screenshots or screen recordings and compose around them.

AI-Generated Assets with Remotion Composition

Remotion can be used as the composition and finishing layer for AI-generated assets.
Example workflow:
Script or prompt
→ AI image/video generation
→ selected clips or images
→ Remotion composition
→ captions, overlays, music, transitions, logo
→ final render
Remotion is not the photorealistic generator. It is the deterministic compositor and renderer.

CI/CD Render Pipeline

Remotion can be integrated into automated pipelines.
Example architecture:
Input JSON
→ queue job
→ render worker
→ Remotion CLI or @remotion/renderer
→ output video
→ upload to S3/R2/GCS
→ save metadata
→ notify user or downstream system
This is useful when video generation is part of a product or internal workflow.

Architecture Options

Existing Website Repo

Placing Remotion inside an existing website repo is reasonable when the video is tightly coupled to the website.
Example:
website/
app/
components/
public/
remotion/
Root.tsx
compositions/
components/
remotion.config.ts
package.json
Best for:
  • One-off website promo videos
  • Videos that reuse website assets directly
  • Small projects where separation would add overhead
Pros:
  • Easy access to existing assets
  • Easy access to brand tokens and components
  • One pull request can update website and video together
Cons:
  • More dependencies inside the website repo
  • More CI complexity
  • More blast radius for coding agents
  • Creative experiments can clutter product code

Monorepo

A monorepo is useful when website and video generation share brand identity, data, or packages but should remain separate applications.
Example:
repo/
apps/
website/
video-studio/
packages/
brand/
colors.ts
typography.ts
spacing.ts
motion.ts
video-schemas/
docs/
DESIGN.md
VIDEO_STYLE.md
AGENTS.md
Best for:
  • Shared design tokens
  • Shared data schemas
  • Website and video development in the same product ecosystem
  • Clean app boundaries with reusable packages
Pros:
  • Shared source of truth
  • Good boundaries
  • Easier agent scoping than one mixed app
  • Better long-term maintainability
Cons:
  • More setup
  • Workspace tooling needed
  • CI needs filtering
  • Agents need clear instructions about which app/package they are editing

Standalone Video-Studio Repo

A standalone video-studio repo is ideal when video generation is its own reusable system.
Best for:
  • Multiple video formats
  • Multiple products or channels
  • Agent-heavy creative iteration
  • Independent rendering pipelines
  • Reusable templates
  • Lower blast radius from product apps
Pros:
  • Cleanest creative sandbox
  • Lower risk to production website code
  • Easier to evolve into a render service
  • Easier to reuse across products
Cons:
  • Brand tokens may need to be duplicated or exported
  • Website and video changes are not atomic by default
  • Requires discipline around design-source synchronization

URL-Only Reference Workflow

A live website URL can be used as a visual reference, but it should not be treated as a reliable design system.
A coding agent may be able to inspect:
  • HTML structure
  • Computed CSS
  • Screenshots
  • Public images
  • Font names
  • Colors
  • Layout patterns
But it usually cannot reliably recover:
  • Source React components
  • Design tokens
  • Tailwind config
  • Original component names
  • Build-time constants
  • Private assets
  • Design rationale
  • Maintainable source structure
Use URL-only workflows for approximation or inspiration. For accurate reusable templates, provide source code, exported brand tokens, design docs, screenshots, and assets.

Repository Documentation

Serious Remotion-agent workflows should include explicit documentation.

AGENTS.md

AGENTS.md  tells coding agents how to work in the repo.
It should include:
  • Which docs to read before visual work
  • Which app/package contains Remotion code
  • Whether to use the Remotion skill
  • What validation commands to run
  • What files should not be touched
  • Whether rendered outputs may be committed
  • Dependency and network rules
Example:
# Agent Instructions

This repository contains Remotion video-generation code.

Before visual or Remotion work, read:

- docs/DESIGN.md
- docs/VIDEO_STYLE.md
- packages/brand/src/colors.ts
- packages/brand/src/typography.ts
- packages/brand/src/motion.ts

Use the Remotion skill if available.

Rules:

- Keep compositions deterministic and data-driven.
- Use typed props or schemas for dynamic content.
- Use Remotion frame-based animation APIs.
- Do not use CSS keyframes or timers for video timing.
- Use local assets unless explicitly allowed.
- Do not commit rendered videos unless explicitly requested.
- Update README when adding compositions or render scripts.
- Validate with typecheck and a still-frame or short smoke render when feasible.

DESIGN.md

DESIGN.md  is the human-readable design system contract.
It should define:
  • Brand feel
  • Color usage
  • Typography rules
  • Layout rules
  • Spacing principles
  • Visual do/don’t examples
  • Accessibility and readability expectations
  • Website-specific rules
  • Video-specific constraints if no separate video doc exists
Example sections:
# Design System

## Brand Feel

Minimal, editorial, high contrast, direct, and readable.

Avoid decorative clutter, excessive gradients, glassmorphism, and random icons.

## Typography

Use large, readable type.
Do not use more than two major font sizes per scene unless necessary.
Prioritize mobile readability.

## Layout

Use generous spacing.
One main idea per screen.
Avoid dense dashboard layouts in video scenes.

## Motion

Motion should support comprehension.
Prefer opacity, translateY, and subtle scale.
Avoid constant movement and overanimated transitions.

VIDEO_STYLE.md

VIDEO_STYLE.md is useful when the repo generates multiple video types.
It should define:
  • Default formats
  • Platform-specific dimensions
  • FPS rules
  • Duration ranges
  • Caption rules
  • Hook timing
  • Scene pacing
  • Transition rules
  • Safe margins
  • Review output requirements
Example:
# Video Style

## Default Formats

- Vertical: 1080x1920
- Square: 1080x1080
- Landscape: 1920x1080
- FPS: 30

## Timing

- The first 2-3 seconds should establish the hook.
- Use one primary idea per scene.
- Captions should remain readable long enough for mobile viewers.

## Motion

Use subtle, frame-driven motion.
Avoid spinning, bouncing, and decorative motion that does not clarify the message.

## Review Outputs

For new compositions, render still frames from major scenes and a short smoke render when feasible.

README.md

The README should explain how humans and agents run the project.
Include:
  • Setup commands
  • Preview command
  • Render command
  • Still-frame command
  • Smoke-render command
  • Output directory policy
  • How to add a new composition
  • How to pass props/data
Example scripts:
{
"scripts": {
"dev": "remotion studio",
"render:daily": "remotion render src/index.ts DailyUpdate out/daily.mp4",
"still:daily": "remotion still src/index.ts DailyUpdate out/frame-30.png --frame=30 --scale=0.25",
"render:daily:smoke": "remotion render src/index.ts DailyUpdate out/smoke.mp4 --frames=0-60"
}
}

Video prompt generation best practices

A coding agent needs a complete video brief.
Prepare:
  • Video goal
  • Target platform
  • Dimensions
  • FPS
  • Duration
  • Output format
  • Scene timeline
  • Copy or script
  • Brand/design source
  • Assets
  • Data/props contract
  • Animation constraints
  • Validation commands
  • Commit/output rules
Bad brief:
Make a cool video for this product.
Good brief:
Create a 20-second vertical Remotion video for LinkedIn/TikTok.

Format:
- 1080x1920
- 30fps
- H.264 MP4

Scenes:
- 0-3s: hook
- 3-8s: feature 1
- 8-13s: feature 2
- 13-18s: proof/result
- 18-20s: outro

Style:
- minimal editorial
- black background
- large readable typography
- subtle motion only
- no neon gradients
- no random icons

Data:
- use typed props
- add example JSON

Assets:
- use local logo from public/logo.svg
- no remote assets

Validation:
- run typecheck if configured
- render frame 30
- run a short smoke render for frames 0-60
- run git diff --check

Do not commit rendered video files.

Remotion Coding Rules for Agents

Use Remotion-native primitives:
  • Composition
  • Sequence
  • AbsoluteFill
  • useCurrentFrame()
  • useVideoConfig()
  • interpolate()
  • spring()
  • staticFile() for local assets
Prefer:
  • typed props
  • schemas when already used by the project
  • deterministic rendering
  • local assets
  • reusable components
  • one clear idea per scene
  • readable mobile typography
Avoid:
  • CSS keyframes for video timing
  • CSS transitions for video timing
  • setTimeout
  • Date.now()
  • unseeded Math.random()
  • remote assets unless explicitly allowed
  • unnecessary dependencies
  • excessive blur or heavy filters
  • unreadable text
  • committing rendered output by default
CSS and Tailwind can be used for layout and static styling. Remotion frame-based APIs should drive the animation.

Validation Workflow

Visual work needs validation artifacts. A typecheck alone is not enough.
Recommended checks:
npm run typecheck
npx remotion still src/index.ts DailyUpdate out/frame-30.png --frame=30 --scale=0.25
npx remotion render src/index.ts DailyUpdate out/smoke.mp4 --frames=0-60
git --no-pager diff --check
Prefer project scripts so agents do not guess command syntax:
{
"scripts": {
"typecheck": "tsc --noEmit",
"dev": "remotion studio",
"still:daily": "remotion still src/index.ts DailyUpdate out/frame-30.png --frame=30 --scale=0.25",
"render:daily:smoke": "remotion render src/index.ts DailyUpdate out/smoke.mp4 --frames=0-60",
"render:daily": "remotion render src/index.ts DailyUpdate out/daily.mp4"
}
}
A good review loop:
agent proposes plan
→ agent implements
→ agent renders still frames
→ human reviews visually
→ human gives concrete critique
→ agent revises
→ smoke render
→ final render
Good visual feedback is specific:
The text is too small for mobile.
The first 2 seconds are not punchy enough.
Reduce motion by 40%.
Use fewer boxes.
Make it more editorial.
The screenshot should be the hero visual, not the background.
The outro feels too long.

Version Control Rules

Track:
  • source code
  • Remotion compositions
  • reusable components
  • design tokens
  • docs
  • schemas
  • example props
  • render scripts
  • small static assets
Usually ignore:
  • generated MP4 files
  • generated WebM files
  • temporary still frames
  • smoke renders
  • cache folders
  • node_modules
Example .gitignore:
node_modules/
out/
renders/
*.mp4
*.webm
*.gif
*.mov
Rendered outputs should only be committed when they are intentional release artifacts.

Live Website Input vs Source Design System

A live website URL is useful as reference material. It is not a reliable design system.
Good uses of a URL:
  • Take screenshots
  • Understand rough visual direction
  • Capture product UI for a walkthrough
  • Extract approximate layout ideas
  • Compare final video against the public brand feel
Weak uses of a URL:
  • Treating computed CSS as maintainable source
  • Reconstructing components from minified bundles
  • Depending on remote assets at render time
  • Assuming the agent can infer the full design system
Better inputs:
  • Source repo
  • Shared brand package
  • DESIGN.md
  • VIDEO_STYLE.md
  • exported tokens
  • local fonts
  • local logos
  • screenshots
  • example videos

Photorealistic Video

Remotion does not generate photorealistic footage by itself.
It can compose photorealistic assets if they are supplied:
  • real video clips
  • product recordings
  • screenshots
  • AI-generated video clips
  • AI-generated images
  • 3D renders
  • stock footage
Remotion is best understood as the programmable editing, motion graphics, and rendering layer.

Common Mistakes

Avoid these mistakes:
  • Asking the agent to “make a cool video” without specs
  • Using a live URL as the only design source
  • Not defining dimensions, FPS, and duration
  • Not defining a scene timeline
  • Hardcoding production content into components
  • Using CSS keyframes or timers for animation timing
  • Adding random dependencies
  • Using remote assets without permission
  • Making text too small for mobile
  • Overusing gradients, cards, blur, and icons
  • Skipping still-frame validation
  • Committing generated video outputs by accident
  • Assuming the MCP renders videos
  • Assuming Remotion generates photorealistic footage
  • Relying only on a global skill with no repo-local instructions
