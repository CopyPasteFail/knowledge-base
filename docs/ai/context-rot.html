Context Poisoning

Definition:
Irrelevant or incorrect information contaminates the working context and influences reasoning.
📌 What it looks like
  • Residual info from earlier tasks shows up where it shouldn’t
  • Model assumes outdated or false facts
  • Inference uses the wrong baseline assumptions
📘 Deeper technical explanation Context poisoning happens when the “active context window” contains semantically strong but irrelevant tokens. Models assign attention weight based on recency, salience, or atypical phrasing. A misleading fragment can shift the probability distribution enough to create incorrect completions.
In human terms: strong noise corrupts the signal.
💡 Example You finish a discussion about Docker images, then ask for a Terraform module example. The output starts referencing container tags out of nowhere because the previous topic remained “hot” in context.
🔧 Mitigation
  • Reset context explicitly
  • Re-establish key facts
  • Provide a fresh, minimal prompt
🟦 Analogy Adding one wrong chemical to a lab sample ruins the entire batch.

Context Distraction

Short explanation: Focus shifts away from the core instruction to secondary, tangential, or overly interesting details.
📌 What it looks like
  • Long tangents
  • Answer over-indexes on background theory
  • The main request gets buried
📘 Deeper technical explanation Distraction often occurs when the model locks onto high-information or unusual tokens. Transformers amplify patterns that appear rich or strongly correlated with past training distributions. If part of the input triggers a “higher-probability narrative,” the model drifts toward it, even if it’s not the goal.
💡 Example You ask: “List three steps to fix slow API latency.” The model generates a long section explaining TCP handshakes and network theory instead of giving the three steps.
🔧 Mitigation
  • Add strong structural constraints: “bullet points only,” “max 5 lines”
  • Move tangential details to a separate request
🟦 Analogy Like an engineer trying to fix a leak but getting distracted explaining how fluid dynamics works.

Context Confusion

Short explanation: The system can’t determine which instructions or references apply to which task.
📌 What it looks like
  • Wrong output format
  • Mixed instruction styles
  • Applying rules from an earlier section to a new prompt
📘 Deeper technical explanation Confusion happens when overlapping instructions create ambiguity in the model’s task embedding. The model tries to infer intent from multiple competing signals, and because it cannot truly “forget,” it sometimes merges them. This is a token-level conflict inside the attention graph.
💡 Example You give two tasks in sequence: summarizing an article and rewriting a paragraph. The system merges them and produces a “summarized rewrite,” which you never asked for.
🔧 Mitigation
  • Partition tasks explicitly
  • Label tasks: “Task A,” “Task B,” “Ignore A while doing B”
  • Issue one instruction per message when precision matters
🟦 Analogy Feeding two different command sets into a robot at once and it tries to follow both.

Context Clash

Short explanation: Two or more valid instructions are logically incompatible, so the output becomes unstable or inconsistent.
📌 What it looks like
  • Tone shifts mid-sentence
  • Output tries to satisfy conflicting constraints
  • Contradictory formatting or style
📘 Deeper technical explanation A context clash is a constraint-violation problem. The model attempts to satisfy both instructions by optimizing toward the highest combined probability. When constraints contradict (concise vs. highly detailed, strict vs. playful), the model oscillates between them, creating hybrid outputs.
💡 Example You ask for “very precise, highly technical explanations,” but also “extremely short answers.” The system produces sentences that are short but overly dense, bordering on unreadable.
🔧 Mitigation
  • Choose one priority
  • Replace conflicting constraints with hierarchical ones: “Concise first; detail only if necessary”
  • Use explicit tradeoffs: “Favor clarity over brevity”
🟦 Analogy Telling someone to “run slowly.”

Quick-Diagnosis Checklist

Use this section when the output looks weird and you want to quickly identify the cause.
If the answer references old topics
→ Likely Context Poisoning
If the answer starts rambling or teaching theory
→ Likely Context Distraction
If the task format is wrong or two tasks merge together
→ Likely Context Confusion
If the output feels internally contradictory
→ Likely Context Clash
If you're not sure which it is
Ask yourself:
  1. Is something irrelevant influencing the answer?
  2. Is the focus drifting away?
  3. Are multiple instructions overlapping?
  4. Are two rules incompatible?
Match the first “yes” to the category.
