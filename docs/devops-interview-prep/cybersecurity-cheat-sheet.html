Modern Security Architecture

FWaaS (Firewall as a Service)

Years ago, when companies kept all their applications and data in single, on-site data centers, they took a “castle and moat” approach to securing their networks, with on-premises firewalls serving as the main access checkpoints.
As companies moved to the cloud, adopted infrastructure- and platform-as-a-service strategies, added more company and employee-owned mobile devices, and began using more SaaS applications, they quickly discovered they no longer had clearly defined network perimeters.
They also found that:
  • Because many applications and data were now running on third-party infrastructure, they no longer had full visibility into, or control over, their entire networks.
  • Since companies and cloud providers share responsibility for security in cloud environments, companies could not depend entirely on cloud providers to oversee all security.
This forced many companies to rethink their approach to security. It also pushed them toward FWaaS to deliver firewall and network security capabilities as part of their cloud infrastructure.
Today, FWaaS helps companies:
  • Aggregate traffic from multiple sources, such as on-site data centers, branch offices, mobile users, and cloud infrastructure.
  • Apply and enforce consistent security policies across locations and users.
  • Gain visibility into and control over networks without deploying physical firewall appliances everywhere.

Zero Trust

Simple definition: Zero Trust is a security framework requiring all users, whether inside or outside the organization’s network, to be authenticated, authorized, and continuously validated before being granted or keeping access to applications and data.
Core idea:Zero Trust assumes there is no traditional trusted network edge. Networks can be local, cloud-based, hybrid, or spread across many locations, with users working from anywhere.

Zero Trust Network Access (ZTNA)

Instead of using a VPN, users connect to corporate resources through a client or a web browser. Requests are evaluated against Zero Trust rules that can include signals from identity providers, devices, and other context.
Where RDP software, SMB file viewers, and other thick-client programs used to require a VPN for private network connectivity, organizations can now privately route TCP and UDP traffic through a security provider’s network, where the traffic is verified and filtered.

SASE (Secure Access Service Edge)

Pronunciation: “sassy”
SASE is the convergence of WAN networking and network security services, such as CASB, FWaaS, and Zero Trust, into a single cloud-delivered service model.
SASE provides a more agile and flexible approach to security that can adapt to the changing threat landscape.
SASE can include:
  • Secure Web Gateway: Protects against web-based threats such as malware, phishing, and data loss.
  • Cloud Access Security Broker: Helps organizations control and secure cloud usage.
  • Zero Trust Network Access: Provides secure access to applications and data, regardless of user location or device.
  • Firewall as a Service: Provides cloud-based firewall capabilities.
  • Data Loss Prevention: Helps protect sensitive data from being leaked or stolen.
SASE can be delivered as a single integrated solution or as a collection of individual services.

Security Products and Controls

CASB (Cloud Access Security Broker) {“Kaz-BEE”}

Links:
  • TechTarget: Cloud Access Security Broker
  • What is a Cloud Access Security Broker (CASB)?
A CASB is cloud-hosted software, on-premises software, or hardware that acts as an intermediary between users and cloud service providers.
A CASB implements access control and policy enforcement for cloud environments. Traffic to the cloud can flow through the CASB solution, enabling it to enforce corporate security policies.
CASBs are designed to protect users from cloud-based threats, such as data breaches, data loss, and unauthorized access to cloud applications. They can inspect traffic to and from cloud applications and block traffic deemed to be a threat.
CASBs can also enforce security policies, such as requiring strong authentication and preventing users from sharing sensitive data with unauthorized users.
CASBs can offer capabilities such as:
  • Firewalls to identify malware and prevent it from entering the enterprise network.
  • Authentication to check users’ credentials and ensure they only access appropriate resources.
  • Web application firewall capabilities to help stop application-level attacks.
  • Data loss prevention to prevent sensitive information from leaving the organization.
Prominent CASB vendors include:
  • Microsoft Defender for Cloud Apps: Provides visibility, control, and threat protection for cloud services, including integration with Microsoft Azure and Microsoft 365.
  • Cisco Cloudlock: Focuses on cloud security and data protection, including data loss prevention, user behavior analytics, and compliance enforcement.

SWG (Secure Web Gateway)

Links:
  • Cloudflare: Secure Web Gateway
An SWG is a cybersecurity product that protects company data and enforces security policies between employees and the internet.
Like a water filter removes dangerous impurities from water, an SWG filters unsafe content from web traffic to stop cyber threats and data breaches. It can also block risky or unauthorized user behavior.
SWGs are designed to protect users from web-based threats, such as malware, phishing, and data loss. They inspect web traffic, including traffic to malicious websites, and block traffic that violates policy.
Common SWG technologies include:
  • URL filtering
  • Anti-malware detection and blocking
  • Application control
Why use an SWG:
In the past, business processes largely took place inside internal corporate networks. With more remote work and cloud computing, organizations depend heavily on the internet. Since internet threats include phishing, malware-infected pages, and data leakage risks, SWGs became important for many organizations.
How SWGs work:
Some SWGs run on proxy servers. A proxy server makes requests and receives responses on behalf of a client device, such as a user’s laptop. For secure web gateways, the proxy can be a physical server or a virtual machine in the cloud.
Other SWGs are software-only and can run on-premises or in the cloud as SaaS. Some SWGs are deployed as on-premises appliances.
No matter how they are deployed, SWGs work in roughly the same way: when a client device sends a request to a website or internet application, the request travels through the SWG first. The gateway inspects the request and passes it along only if it does not violate security policies. Incoming data is also inspected before it reaches users.
Because SWGs can run anywhere, they are especially useful for managing remote employees.

EPP (Endpoint Protection Platform)

An EPP is a set of software tools and technologies that secure endpoint devices. It is a unified security solution that can combine antivirus, antispyware, intrusion detection or prevention, personal firewall capabilities, and other endpoint protections.
In most cases, EPP solutions involve installing software or agents on endpoints. The agent provides real-time monitoring, threat detection, and prevention of malicious activity.
By having a presence on the endpoint, the EPP can analyze and block potentially harmful processes, files, or network connections.
Examples of endpoints include:
  • Desktop computers
  • Laptop computers
  • Mobile devices
  • Servers
  • Internet of Things devices
  • Point-of-sale systems
  • Industrial control systems
  • Embedded systems, such as ATMs, medical devices, or digital signage

SIEM (Security Information and Event Management)

Pronunciation: “sim”, with a silent “e”
SIEM is a field within computer security where software products and services combine security information management and security event management.
SIEM systems provide real-time analysis of security alerts generated by applications, servers, databases, networks, and security tools. They are also used to log security data and generate compliance reports.
The term SIEM was coined by Mark Nicolett and Amrit Williams of Gartner in 2005.
Common SIEM attributes include:
  • Retention: Stores data for long periods so decisions can be made using more complete data.
  • Dashboards: Visualizes data to identify patterns and suspicious activity.
  • Correlation: Groups related events together to turn raw data into useful information.
  • Alerting: Triggers alerts when data indicates suspicious or risky behavior.
  • Data aggregation: Collects data from servers, networks, databases, software, and email systems.
  • Compliance: Helps collect and retain data needed for regulatory or policy compliance.

Web Application Firewall (WAF)

Links:
  • Cloudflare: What is a Firewall?
  • Cloudflare: CSRF
  • Cloudflare: XSS
  • Cloudflare: SQL Injection
A WAF helps protect web applications by filtering and monitoring HTTP traffic between a web application and the internet.
It typically protects web applications from attacks such as cross-site request forgery, cross-site scripting, file inclusion, SQL injection, and other application-layer attacks.
A WAF is a Layer 7 defense in the OSI model. It is not designed to defend against every type of attack, so it is usually part of a broader security stack.

Data Loss Prevention (DLP)

Links:
  • Cloudflare DLP
Data loss prevention, sometimes also called data leak prevention, information loss prevention, or extrusion prevention, is a strategy to reduce threats to critical data.
Cloudflare DLP inspects HTTP/S traffic and files, such as Microsoft Office documents, for sensitive data such as credit card information and social security numbers. After identifying the data to protect, DLP profiles can be configured with allow or block policies to prevent information from leaving corporate tenants.
DLP commonly works by classifying content inside data objects and applying automated protection policies.
A multilayered DLP strategy helps sensitive information stay protected and can help organizations review and update data storage and retention policies for compliance.

FIDO2

Links:
  • https://www.youtube.com/watch?v=DWrLBwi7ZBA&ab_channel=DevOpsDaysSeattle
  • https://www.youtube.com/watch?v=F_E2LZK-bFk&ab_channel=LawrenceSystems
  • https://www.youtube.com/watch?v=ybn9J4QCqK4&ab_channel=CrosstalkSolutions
  • https://www.youtube.com/watch?v=fzUVrz0ixn8&ab_channel=AllThingsSecured
FIDO2 is a joint effort between the FIDO Alliance and the World Wide Web Consortium to create strong authentication for the web.
At its core, FIDO2 consists of:
  • W3C Web Authentication, also called WebAuthn
  • FIDO Client to Authenticator Protocol 2, also called CTAP2
FIDO2 enables users to authenticate to online services using common devices in mobile and desktop environments.

Privacy Access Tokens

Links:
  • Fastly: Private Access Tokens
Privacy Access Tokens allow users to verify that they are legitimate users without showing a CAPTCHA.
PATs are designed to be more privacy-respecting and less intrusive. They use cryptography to generate a token that can authenticate a user without requiring direct user interaction.
Benefits of PATs include:
  • They provide an invisible, private way to validate that real users are visiting a website.
  • They help identify HTTP requests from legitimate devices and people without compromising identity or personal information.
  • They reduce friction by avoiding human CAPTCHA interactions.
  • They improve privacy by validating users without fingerprinting or leaking non-essential data.

OWASP Rules

Links:
  • What is OWASP and OWASP Membership
Full name: Open Web Application Security Project
OWASP is an online community that produces freely available articles, methodologies, documentation, tools, and technologies in web application security.
OWASP rules are security guidelines and best practices aimed at preventing common web application vulnerabilities and improving web application security.

Attack Surface Management

Short name: ASM
Attack Surface Management is an approach to cyber defense that assesses and monitors external and internal assets for vulnerabilities and risks that could impact an organization.

Security Product Comparisons

SWG vs CASB

SWG and CASB are distinct but complementary security solutions.
SWG focuses on securing web traffic and protecting users accessing the internet through web browsers. CASB focuses on securing cloud services and cloud data accessed by organizations.
SWG provides features such as URL filtering and malware protection. CASB provides features such as cloud application discovery, access control, and data loss prevention.
In general:
  • SWGs are useful for organizations concerned about web-based threats.
  • CASBs are useful for organizations concerned about cloud-based threats.
  • Many organizations use both together for broader web and cloud security coverage.
When choosing between SWG and CASB, consider:
  • The size and complexity of the organization
  • The types of data stored and processed
  • The types of cloud applications used
  • Budget

EPP vs SWG

EPP focuses on securing endpoints, such as desktops, laptops, servers, and mobile devices. It typically includes capabilities like antivirus, anti-malware, host-based intrusion prevention, and behavior monitoring.
SWG focuses on securing web traffic and enforcing security policies for web browsing. It acts as a proxy between users and the internet, inspecting web traffic for threats, controlling website access, filtering content, and preventing malware infections or data leaks.
In short:
  • EPP protects endpoints from local and endpoint-targeted threats.
  • SWG protects users and organizations from risky or malicious web traffic.

Web and Application Attacks

Client-Side Code

Links:
  • Cloudflare: Client-side vs Server-side
Client-side code is code that runs on a user’s machine. On websites, it is usually code executed by the browser after the page loads.
This is different from server-side code, which runs on the host’s web server.
Client-side code is useful for interactive webpages because interactive content can run faster and more reliably when the browser does not need to communicate with the web server for every interaction.
Client-side code is common in modern web development and is used by most modern websites. Because of this, client-side vulnerabilities such as cross-site scripting are common web security issues.

JavaScript Injection

Links:
  • #3 Hacking 101 - JavaScript injection - web security tutorial
JavaScript injection is a type of attack in which an attacker injects malicious JavaScript code into a website.
That code can then be executed by the victim’s browser, allowing the attacker to steal sensitive information, hijack sessions, or take other malicious actions.
Common injection methods include:
  • Exploiting vulnerabilities in the website’s code.
  • Tricking a victim into clicking a malicious link that downloads or executes malicious code.
Once malicious JavaScript executes, it can:
  • Steal sensitive information, such as credit card numbers or passwords.
  • Hijack sessions and take control of a victim’s account.
  • Deface the website.
  • Send spam or perform other unwanted actions.
Ways to reduce JavaScript injection risk include:
  • Use a WAF to block common attack vectors.
  • Keep website code and dependencies up to date.
  • Validate and sanitize input.
  • Apply strong content security policies where possible.

DNS Amplification

Links:
  • DNS amplification attack
DNS amplification is a DDoS technique where an attacker sends requests to open DNS servers using a spoofed source IP address. The DNS servers send large responses to the victim’s IP address instead of the attacker.
A simple analogy: someone calls a restaurant and says, “I’ll have one of everything, please call me back and repeat my whole order,” but gives the victim’s phone number as the callback number.
With little effort, the attacker causes large responses to be sent to the victim.

Cross-Site Request Forgery (CSRF)

Links:
  • Cloudflare: Cross-Site Request Forgery
CSRF is a type of confused deputy attack that tricks a user into accidentally using their credentials to trigger a state-changing action, such as transferring funds, changing an email address, or changing a password.
Example attack flow:
  1. An attacker creates a forged request that transfers money from a bank account to the attacker’s account.
  2. The attacker embeds the forged request into a hyperlink and sends it in emails or places it on websites.
  3. A victim clicks the link, causing the victim’s browser to send the request to the bank.
  4. The bank receives the request, sees the victim is authenticated, and treats the request as legitimate.

Local File Inclusion (LFI)

Local File Inclusion is a vulnerability that allows an attacker to include and potentially execute files on a target system. This can lead to unauthorized access, information disclosure, or code execution.
Example:
A website has a page that includes image files based on a user-supplied parameter:
<?php
$image = $_GET['image'];
include('images/' . $image);
?>
An attacker could exploit this by causing the application to include an unintended or malicious file.

SQL Injection (SQLi)

Links:
  • Cloudflare: SQL Injection
  • What Is SQL Injection?
SQL injection is a code injection technique used to modify or retrieve data from SQL databases.
By inserting specialized SQL statements into an input field, an attacker may be able to execute commands that retrieve, modify, or destroy data.
With successful SQL injection, an unauthorized user may be able to:
  • Spoof the identity of a more privileged user.
  • Make themselves or others database administrators.
  • Tamper with existing data.
  • Modify transactions and balances.
  • Retrieve or destroy server data.
In severe cases, SQL injection can lead to deeper system compromise.
Simple analogy:
A man named Bob is on trial. Before appearing before a judge, he writes his name as “Bob is free to go.” When the judge reads aloud, “Now calling Bob is free to go,” the bailiff lets Bob go because the judge said so.
The core issue is that the system treats attacker-controlled input as instructions instead of just data.

Magecart Attack

Also known as: web skimming, digital skimming, formjacking
Magecart refers to several hacker groups that use online skimming techniques to steal personal data from websites, most commonly customer details and credit card information on ecommerce sites.
The name is inspired by Magento, an ecommerce platform with checkout and shopping cart functionality.
Magecart attacks can involve:
  • Targeting a small number of high-value organizations.
  • Mass attacks against many vendors.
  • Code injection and skimming scripts.
  • Supply chain attacks through third-party vendors.
  • Targeting ecommerce platforms and checkout pages.

Cross-Site Scripting (XSS)

Links:
  • Cloudflare: Cross-Site Scripting
Cross-site scripting is an exploit where an attacker attaches malicious code to a legitimate website. That code executes when a victim loads the website.
The malicious code can be inserted in several ways. It may be added to the end of a URL or posted directly onto a page that displays user-generated content.
In technical terms, XSS is a client-side code injection attack.
Example:
An attacker posts a comment on an unvalidated comment forum. The comment contains executable code wrapped in <script></script> tags. When another user loads the page, the browser executes the malicious code and the user becomes a victim of the attack.

Bot and Automation Abuse

JavaScript Challenge

Links:
  • Engaging Networks: JavaScript Challenge
A JavaScript challenge is a method used in bot detection and DDoS mitigation to filter requests that look like botnet or malicious automated traffic.
The server sends JavaScript code that includes a challenge. Legitimate browsers usually have a JavaScript engine and can complete the challenge automatically. Many basic bots cannot execute JavaScript or interact with page elements like a human user, so they fail the challenge.
By implementing a JavaScript challenge, website operators can filter suspicious traffic while allowing most legitimate users through.

Scalping Bots

Links:
  • OWASP: Scalping Bots
Scalping bots acquire goods or services through an application in a way that a normal user could not do manually.
A common example is snapping up inventory quickly and reselling it at inflated prices on third-party sites.

Headless Browsers and Headless Systems

“Headless” generally refers to software or a system that operates without a graphical user interface. It usually focuses on backend functionality or services without a traditional visual interface.
Common types of headless implementations include:
  • Headless CMS: Separates content creation and management from the presentation layer, allowing content to be delivered through APIs to different front ends.
  • Headless ecommerce: Decouples the front-end shopping experience from backend commerce functionality.
  • Headless API: Provides access to core system functionality without user interface components.
  • Headless browser: Runs without a graphical user interface and is commonly used for automated browsing, scraping, testing, and scripted interaction with webpages.
A CMS, or content management system, is software that helps users create, manage, and modify website content without needing to write code from scratch.

Credential Stuffing

Credential stuffing is an attack where stolen login credentials from one service are used to try to break into accounts on another service.

Credit Card Stuffing

Also known as: carding
Credit card stuffing is an attack where bots are used to try checkout flows with stolen credit card details.

Inventory Hoarding

Also known as: denial of inventory
Inventory hoarding is an ecommerce attack where items are taken out of circulation by adding many of them to carts or baskets. The attacker does not complete checkout, but the behavior can contribute to a stock-out condition.

Knowledge-Check Q&A

Name common compliance frameworks

ISO 27001
A framework that defines how an organization should manage and protect information securely through policies and controls.
SOC 2
A standard that evaluates whether a company properly protects customer data based on security and availability principles.
PCI-DSS
A mandatory security standard for companies that store, process, or transmit credit card information.
HIPAA
A U.S. regulation that protects sensitive healthcare and medical information.

Follow-up: What does compliance mean from a DevOps perspective?

From a DevOps perspective, compliance means enforcing security technically, not just documenting it: implement least-privilege IAM, ensure all infrastructure changes go through auditable CI/CD pipelines, enforce encryption at rest and in transit, centralize logs with proper retention, store secrets in a secure manager, run regular vulnerability scans, test backups and disaster recovery, separate environments clearly, and maintain strict role-based access controls. For PCI and HIPAA in particular, you also need strong network segmentation, tighter access restrictions, detailed audit trails, and proper handling or masking of sensitive data.
